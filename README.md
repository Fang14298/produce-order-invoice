## ✨ ฟีเจอร์

* **ออกเอกสาร 2 ใบต่อ 1 ออเดอร์ (ใบรับสินค้า + ใบส่งสินค้า/ใบแจ้งหนี้)**: เมื่อเลือกออเดอร์ 1 รายการ ระบบจะสร้างเอกสารเรียงต่อกัน 2 ใบเสมอ โดย **ใบรับสินค้า มาก่อน** แล้วตามด้วย **ใบส่งสินค้า / ใบแจ้งหนี้** ทั้งสองใบใช้เทมเพลตเดียวกันผ่านฟังก์ชัน `buildDocBlock(order, fee, variant)` (`variant` = `"receipt"` หรือ `"invoice"`) จึงแก้หน้าตาบิลที่เดียวแล้วมีผลทั้งคู่ ความต่างของ **ใบรับสินค้า** คือ:
  * หัวเอกสาร (`.inv-doc-title`) เป็น **"ใบรับสินค้า"**
  * ตารางสินค้าเหลือ 4 คอลัมน์ (No. / รายการ / จำนวน / หน่วยนับ) — ตัด **ราคา/หน่วย** และ **จำนวนเงิน (บาท)** ออก
  * ไม่มีกล่องชำระเงิน (`.inv-payment-box` พร้อม PromptPay QR) และไม่มีสรุปยอด (`.inv-totals`)
  * ช่องลายเซ็นฝั่งขวาเป็น **"ผู้รับสินค้า"** (ไม่มีคำว่า "ผู้ชำระเงิน" เพราะใบนี้ไม่เกี่ยวกับการรับเงิน)
  * ยังคงแสดง หัวบิล/ข้อมูลลูกค้า/หมายเหตุ/ลายเซ็น เหมือนใบแจ้งหนี้ทุกประการ
* **อ่านข้อมูลสด ไม่ต้องมี backend เพิ่ม**: ดึงออเดอร์ทั้งหมดจากชีต `"รายการออเดอร์"` ของ Google Sheet เดียวกับ `produce-order` ผ่าน Google Visualization API (`gviz/tq`) — อ่านอย่างเดียว ปลอดภัย ไม่ต้องแก้ Apps Script ข้อกำหนดเดียวคือชีตต้องแชร์แบบ *"ทุกคนที่มีลิงก์ - ผู้มีสิทธิ์ดู"*
* **ระบบกรองออเดอร์ (Filters) & ค้นหา**:
  * ค้นหาด้วยเลขที่ออเดอร์ / ชื่อลูกค้า / เบอร์โทร 
  * กรองตาม **วันที่ส่งสินค้า** และ **สถานะออเดอร์** จาก Dropdown
* **เลือกพิมพ์บิลพร้อมกันหลายใบ (Batch Selection)**:
  * มี Checkbox หน้าแต่ละออเดอร์ให้เลือกทีละหลายรายการ
  * มีปุ่ม **"เลือกทั้งหมด (ที่กรองไว้)"** เพื่อเลือกออเดอร์ตามเงื่อนไขที่ค้นหา/กรองไว้
  * ระบบจะสร้างเอกสารเรียงต่อกันอัตโนมัติ ออเดอร์ละ 2 ใบ (ใบรับสินค้า + ใบส่งสินค้า/ใบแจ้งหนี้) เช่น เลือก 3 ออเดอร์ = ได้เอกสาร 6 ใบ 6 หน้า
* **แปลงข้อความสรุปกลับเป็นตารางรายชิ้น**: อ่านคอลัมน์ `รายการสินค้าที่สั่ง` แล้วแยกกลับเป็นแถวสินค้า (ชื่อ/จำนวน/หน่วย/ราคาต่อหน่วย/จำนวนเงิน) ด้วย regex
* **แปลงวันที่จาก Google Sheets ให้อ่านง่าย**: คอลัมน์ที่เป็นชนิด Date ในชีต (เช่น `วันที่รับของ`, `วัน-เวลาสั่งซื้อ`) เมื่ออ่านผ่าน GViz จะได้ค่าดิบเป็นข้อความรูปแบบ `Date(YYYY,M,D)` หรือ `Date(YYYY,M,D,H,Mi,S)` (เดือนเริ่มนับที่ 0 ตามสเปคของ Google) ฟังก์ชัน `parseGvizDate()` ในหน้าเว็บจะแปลงค่านี้ให้เป็นรูปแบบไทย `DD/MM/YYYY` (เช่น `12/08/2026`) เสมอ — **แสดงเฉพาะวันที่ ไม่แสดงเวลา แม้ค่าดิบจะมีเวลาติดมาด้วยก็ตาม** (ส่วนเวลาถูกตัดทิ้งโดยตั้งใจ ไม่ได้ใช้งานในบิล) ดังนั้น dropdown "กรองตามวันที่ส่งสินค้า" จึงเรียงตามลำดับเวลาจริงด้วยฟังก์ชัน `compareThaiDate()` แทนการเรียงแบบ string เพื่อไม่ให้ผลลัพธ์สลับเดือน/วันผิดพลาด
* **แปลงตัวเลขจากชีตอย่างปลอดภัย**: คอลัมน์ `ยอดรวม` อาจถูกเก็บเป็นข้อความที่มีตัวคั่นหลักพัน เช่น `"1,234.00"` ซึ่ง `Number("1,234.00")` จะได้ `NaN` แล้วตกไปเป็น `0` เงียบๆ ทำให้ทั้งยอดในบิลและยอดที่ล็อกใน PromptPay QR ผิด ฟังก์ชัน `toNumber()` จึงตัด comma และช่องว่างออกก่อนแปลงเป็น `Number` เสมอ (ถ้าแปลงไม่ได้จริงๆ จึง fallback เป็น `0`)
* **PromptPay Dynamic QR Code ล็อกยอด**: สร้าง QR ตามมาตรฐาน EMVCo ด้วยไลบรารี `qrcode-generator` (ออฟไลน์ ไม่พึ่ง API ภายนอก) ล็อกยอดเงิน = ยอดรวมออเดอร์ + ค่าจัดส่ง (ปรับได้ในหน้าเว็บ เพราะชีตยังไม่ได้แยกเก็บค่าส่ง)
* **ป้องกัน HTML Injection จากข้อมูลในชีต**: ทุกฟิลด์ที่มาจากผู้ใช้/ชีต (ชื่อลูกค้า, เบอร์โทร, ที่อยู่, เลขผู้เสียภาษี, หมายเหตุ, ชื่อ/หน่วยสินค้า, สถานะ, วันที่กรอง) ถูกแปลงผ่าน `escapeHtml()` ก่อนแทรกลง `innerHTML` เสมอ เพื่อไม่ให้อักขระ `<`, `>`, `&`, `"` ที่หลุดเข้ามาในชีตทำให้โครงสร้างบิลเพี้ยนหรือรันโค้ดแปลกปลอมได้
* **ปุ่มพิมพ์บิล**: `window.print()` พร้อม CSS `@page { size: A4 }` รองรับการพิมพ์ทีละหลายหน้าโดยมีการบังคับขึ้นหน้าใหม่ (`page-break-after: always`) ที่ `.inv-block` ทุกใบ ดังนั้น **เอกสาร 1 ใบ = กระดาษ 1 แผ่น** (ใบรับสินค้าและใบแจ้งหนี้ของออเดอร์เดียวกันจะไม่ปนอยู่หน้าเดียวกัน)
* **ปุ่มดาวน์โหลด PDF**: แปลงบิลเป็นภาพด้วย `html2canvas` แล้วสร้างไฟล์ PDF ขนาด A4 ด้วย `jsPDF` ดาวน์โหลดเป็น `ใบรับ-ใบส่งสินค้า-batch.pdf` (หรือชื่อออเดอร์ถ้าเลือกออเดอร์เดียว) ฟังก์ชัน `computePageSlices()` คำนวณจุดตัดหน้าจากตำแหน่งจริงของแต่ละบล็อก (หัวบิล/ข้อมูลลูกค้า/แถวสินค้า/หมายเหตุ/สรุปยอด/ลายเซ็น) เพื่อไม่ตัดกลางแถวหรือกลางบล็อกสำคัญ — เมื่อพิมพ์หลายบิลพร้อมกัน (Batch) แต่ละใบจะถูกคำนวณแยกกัน หากตารางสินค้าของ**ใบใดใบหนึ่ง**ยาวเกินหนึ่งหน้า ระบบจะซ้ำหัวตารางของ**ใบนั้นเอง**ในหน้าถัดไปโดยอัตโนมัติ (ไม่ใช้หัวตารางของใบแรกผิดใบ)

> ℹ️ **Cache-Busting**: ตอนโหลดหน้าเว็บ โค้ดจะคำนวณค่าคงที่ `LOGO_SRC = "LOGO.PNG?v=" + Date.now()` หนึ่งครั้ง แล้ว `renderInvoices()` นำไปใส่ใน `src` ของ `<img class="inv-logo-img">` ทุกใบ — ผล query string `?v=<timestamp>` ที่เปลี่ยนทุกครั้งที่เปิดหน้าเว็บ บังคับให้เบราว์เซอร์โหลดภาพใหม่เสมอ ไม่ติดปัญหารูปเก่าค้างใน Cache แม้จะแทนที่ไฟล์ `LOGO.PNG` โดยใช้ชื่อเดิม (ค่าเดิมถูกใช้ซ้ำตลอดอายุหน้าเว็บ จึงไม่ยิงโหลดโลโก้ใหม่ทุกครั้งที่ re-render บิล)
